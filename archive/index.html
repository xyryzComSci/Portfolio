ENTRY NO. 001 — PERSONAL / CLIENT-ADJACENT PROJECT
Shipped

RentFlow — AI-assisted billing automation

Replaced a manual monthly cycle of reading 46 meters and computing 22 invoices by hand for a 23-unit rental property. The operator now runs the full billing cycle from a Telegram chatbot.

How the gate works: a Google Gemini vision model reads handwritten meter sheets into structured data, but every machine-read value is staged for human review — nothing reaches an invoice unverified. The operator gets a draft cycle summary in Telegram and reviews it before typing /send to dispatch.

The other four workflows — 43 nodes total
Judgment call

The original build was 20 workflows and 422 nodes — robustness expressed as node-count. I concluded that was solving the wrong problem: more moving parts made the system harder to troubleshoot and hand over, not safer. Redesigning down to 5 workflows and 43 nodes turned out to be the actual reliability improvement — and a dedicated error-handler workflow means a failure gets reported to the operator in plain words, not buried in a log nobody opens.

Revisions, handled

Telegram was chosen as the interface after weighing it against a dashboard — the operator already lives in the app, so meeting them there removed a login step entirely. From there, real revision cycles: arrears handling, using the move-in-date reading as the correct utility baseline instead of the cycle start, and switching delivery from a plain email to a rendered invoice image after the operator asked for something a tenant could actually read at a glance.

In progress — Telegram bot upgrade from strict command syntax to semantic requests, with button-based confirmation replacing typed commands.

ENTRY NO. 002 — UNIVERSITY DELIVERY / THESIS PROJECT
Delivered

HERC — Human Ethics Review Board System

Replaced VSU's paper-based Research Ethics Review Board process with a centralized platform spanning 4 user roles and 3 review workflows, ending campus-wide hand delivery of printed protocol documents.

How the gate works: protocols move through role-scoped review stages — no submission advances without the assigned reviewer's sign-off, digitally reproducing the accountability the paper trail used to carry.

Judgment call

The hardest part wasn't the build — it was mapping an existing paper procedure onto software without quietly changing who's accountable for what. I ran the engagement end-to-end with university stakeholders, agreeing on the redesigned workflow before writing code, rather than digitizing the paper form as-is.

In progress — n8n agent that assesses a submitted protocol's likely review type, with direct text references to the reviewer's manual guidelines, for the head reviewer to confirm.

ENTRY NO. 003 — FREELANCE CLIENT PROJECT
In progress

MUPO Dashboard — student org management platform

Admin console and bulletin system for SSU's Municipal Psychology Student Organization — tiered permissions, a registration approval gate, and storage-quota guards, built for a six-committee structure.

How the gate works: row-level security is the real access-control layer, not just the UI — every role's permissions are enforced at the database. New registrations clear two separate steps: an email confirmation, then a manual Sys Admin approval, so identity and authorization are never conflated into one click.

Judgment call

Chose a link-first, hybrid file storage model with a 1GB quota guard instead of storing uploads directly — trading a small amount of user convenience for a system that won't silently run out of room or become expensive to maintain as the org's content grows.
